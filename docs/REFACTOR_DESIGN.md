# Finish the refactor properly: a Qt-free controller core, lossless paths, and eight gaps in `docs/REFACTOR_PLAN.md`

Status note (2026-11-06): the Context describes the code as of the 2026-11-02 check. REFACTOR_PLAN.md's ledger records what has since been closed (S-12.4 to S-12.22, and S-17.1 to S-17.8 for names). The claim in line 13 that S-12.3 has `#[qenum]` filter types was not true of the code: `MediaKind` is the only `#[qenum]`. Status (2026-11-08): `docs/REFACTOR_PLAN.md`'s ledger is the status source; this file is the design, and its Context is the 2026-11-02 state.

## Context

Two audits, one of the code (S-12) and one of `docs/REFACTOR_PLAN.md`, found the refactor short of the goal of the most proper design. A third review, which asked whether the proposed architecture is the most proper one, found three more gaps: **(a)** policy still lives in QML and is only being moved piecemeal, not into one testable core; **(b)** file names and paths are lossy `String`s; **(c)** the QML/cxx-qt assumptions were unproven. All spikes have been run (results below). Two design reviews then stress-tested the core and the path type, and a fourth review compared seven alternative architectures against the spike data (see "Alternatives considered"); the corrections from all of them are folded in. **That fourth review changed the design:** the controller is a set of small sub-machines with sans-IO time, the data owners (`GalleryModel`, `FolderModel`) keep their `Grid`/`Tree`, and nothing depends on the undecided web stack. Churn is accepted in exchange for the most proper design.

**S-12 is incomplete in the code (verified, not taken from the ledger):**

- JSON still crosses the Rust/QML bridge: `GalleryModel.open_folder(.., query, sort, ..)` (`gallery.rs:150,446`), `View` (`sort_json`, `session_query`, `save_session(query)`, `save_view(name, query)`, `apply_view`), `Filters.query`/`counts`, `FacetChoices.query`/`counts` (`facet_choices.rs:127-155`). QML only relays it.
- Magic values: the -1/1/0 facets (`FilterBar.qml:191-192,219-220`), facet names as strings, `viewed_kind` as `"image"/"animated"/"video"` (`Viewer.qml:71-75`, `MediaView.qml:47,114`, `Hud.qml:91`, `keymap.rs:109`), hand-synced action-code enums (`Main.qml:327`, `Viewer.qml:233`), `fullUrl(key, "full")`, `image://` strings built in QML, `Main.sortKeys` beside an unused `View::SortKey`.
- Controller logic in `Main.qml` (618 lines): the start gate (`gridLoaded`/`treeLoaded`/`started`), anchor policy, `select`, the `gridKey` switch, `openPath`/`applyView`, four debounce Timers, `toggleBorders`, the sort-choice policy.
- Open `REVIEW.md` rows: R-120, R-81, R-119, R-96, R-79.
- The S-13.1 ledger row says `pg-desktop` depends only on the Qt crate and `pg-app`; `crates/desktop/Cargo.toml` lists eleven workspace crates. S-12.3's row claims `#[qenum]` filter types the code does not have. The Yandex results panel was never pixel-checked.

**Names are lossy (verified by reading; `library/src/scan.rs:61-66`, pinned as intended by the test at `scan.rs:189-208`):** a NTFS name with an unpaired surrogate is stored with U+FFFD; the folder walk builds the child path from the lossy name (`scan.rs:142`) so the folder can no longer be opened and everything under it is invisible; files are stored lossy and reopened from the stored string (`import.rs:95`, `thumbs.rs:86`, `borders.rs:57`) and fail. Folders with names that differ only in lone surrogates merge into one row (`folders.path TEXT UNIQUE`, `catalog/lib.rs:103`). File rows cannot collide (`UNIQUE(volume, file_ref)`). On Unix the conversion is worse (`platform/dir.rs:195`, `file.rs:38`: bytes to U+FFFD to UTF-16 and back).

**The plan itself falls short in eight places:** (1) verification is manual, no screenshot harness exists and `pg-desktop` has `test = false`; (2) performance is measured once at the end (S-13.5 still open) with `lto = false` across 24 crates; (3) `pg-model` is tied to Windows (paths, `FileIdentity`, `Ext::of_name_utf16`) while the goal includes a web server; (4) parsers of untrusted files are only unit-tested; (5) no localisation seam, QML literals remain (S-10.8); (6) crate granularity is inconsistent (`pg-library` bundles seven passes and 12 dependencies); (7) the per-component facades are a qmlcachegen workaround written down as architecture; (8) there is no CI and `just wsl-check` runs only clippy.

## Design decisions

- **The web client's stack is undecided, and nothing in this plan depends on it.** `docs/WEB_CLIENT.md`'s Svelte 5 + TypeScript verdict is a research recommendation, not a decision; Qt for WebAssembly is an open check there. So the controller is **not** claimed to be reused by the web, and the plan makes no choice that a Qt-WASM, a TS, or a Rust-WASM web client would regret. The cheap constraint kept: `pg-model` and `pg-client` stay wasm32-clean (no `std::time::Instant`, threads or files; enforced by a per-crate `clippy.toml` `disallowed-types`/`disallowed-methods`, not only by the compile check). What both UIs need, they get as **data and types**, not as a shared controller: sort choices, facet definitions, key labels and the `Key -> action` map, the URL grammar, the `Query`/`Listing` types (specta), the layout function, and Fluent `.ftl` strings (which `@fluent/bundle` can also read). The old docs' line "the web client can reuse `pg-client`" is corrected in S-12.22 to say this.
- **One controller in `pg-client` (`pg_client::controller`), built from small sub-machines.** A single entry `Controller::update(now_ms, Event) -> Vec<Command>` routes to independently tested sub-machines, each with its own state, event and command enums: `StartGate` (tree/list/layout), `Listing` (folder, recursive, sort, query, apply-view, `OpenList`), `Input` (key to action; selection decisions), `Deadlines` (debounce), `Panels` (filters/borders/viewer-open flags), `Prefs` (row height, thumb height, save timing). No god-enum. It is pure; it owns policy, not data. The desktop becomes a projection: Qt input in as `Event`s, `Command`s executed.
- **Where the instance lives:** NOT in `pg_app::App` (process-global and `Sync`, no change notification; a `Mutex` plus a command that raises an event deadlocks). The type is in `pg-client`; the one instance lives on the GUI thread, owned by a thin QObject `Shell` (created by id in `Main.qml`). The registry of `CxxQtThread` handles is a **GUI-thread `thread_local`** (not a `static Mutex`), and there is exactly one cross-thread entry point, `Shell::post(Event)` (S8b: per-thread order holds), which workers use for results. `pg-app` keeps persistence only (`Place`/`save_place`, prefs). **No new `pg-app -> pg-client` edge.**
- **`Listing` is `pg_model::view::Place` renamed** (`{folder, recursive, sort, query}`), not a new type; the `place()`/`save_place()`/`views` table are its persistence. The stored format is redesigned where better (see "No compatibility"), then pinned by goldens.
- **Data stays with its owner.** `GalleryModel` keeps its `Grid` and `FolderModel` its `Tree`. Checked in the code: `Grid` is already a pure `pg-client` struct with `plan`/`commit`/`arrive`/`release_held`/`selection_after`/`placement().neighbor`, all unit-tested (`grid.rs`, `layout.rs`), so geometry and selection mechanics are already testable without Qt. Moving ownership into a shared `RefCell` core (spike S9) would add a borrow protocol, a thread-local core and a rewrite of `gallery.rs` and `folders.rs` for a benefit that already exists. The division is: the **core decides** (what should happen) and the **data owner executes** (how, with the tested pure functions). The core knows only scalar facts (`current`, `anchor`, `count`, loaded/laid-out flags, `viewer_open`), sent as events. S9 stays as evidence that the shared-core protocol works if a concrete need ever appears.
- **Commands are two kinds.** *Model commands* execute in Rust on the data owner (`OpenList`, `Relayout`, `SetRating`, `Rotate`, `SetBorderMark`, `SetThumbHeight`, `SaveSession`, `SavePrefs`, `CountFacets`, `StepSelection{dx,dy}`, `SelectItem`; `StepSelection` runs `placement().neighbor` inside `GalleryModel`). *Presentation commands* are typed `Shell` signals routed by one annotated `Connections` handler each (`ScrollGrid{item, mode}`, `ScrollTree{row}`, `FocusGrid`, `ShowViewer(i)`, `OpenPanel(kind)`; about six): ListView and Loader state cannot be reached from Rust. `ScrollGrid` carries an item; the handler calls `galleryModel.rowOf(item)`.
- **Re-entrancy rules.** (1) Every Event raised from inside a Rust model is posted (`qt_thread().queue`), never dispatched inline: `GalleryModel::apply` holds `Pin<&mut Self>` while it emits. (2) A dispatch's Commands execute in order through the same queue. (3) `dispatch()` is a trampoline: `update`, then drain a `VecDeque<Event>`.
- **Time is sans-IO, not a command (changed).** The core never sleeps or spawns. The host passes a monotonic `now_ms: u64` (not `std::time::Instant`, which panics on wasm32-unknown-unknown) with every event; the `Deadlines` sub-machine stores one deadline per debounce id (re-arming overwrites the entry), and the core exposes `next_deadline() -> Option<u64>` and `handle_timeout(now_ms) -> Vec<Command>`. The desktop executor is **one** single-shot `QTimer` in C++ glue (the project already does this in `cpp/screenshot.cpp` and `cpp/live_reload.cpp`; cxx-qt-lib 0.10 has no `QTimer`), re-armed to `next_deadline()` after each dispatch. The spike's thread-per-arm timer is dropped (it spawns a thread per keystroke). A `Quit`/shutdown event drains the pending deadlines so `SaveSession`/`SavePrefs` are never lost. Replay becomes `(now_ms, Event)` lines with no fake clock. **Which timers move:** `applyTimer` (300 ms query debounce), `sessionTimer` (1 s), `thumbTimer` (300 ms) and `layoutTimer` (50 ms) change state or issue commands, so they go to the core; `Viewer.zenTimer` (the controls auto-hide, interval from Qt's `mouseDoubleClickInterval`), `ImageLayers` region timer, `YandexPreview.centre` (interval 0, a next-pass layout hack) and `TestHooks` stay in QML as presentation. Rule: a timer that changes app state or issues a model command is core; one that only animates or hides chrome is QML.
- **Control-flow input facts, not Qt codes.** `Event::Key` carries `pg_client::Key`; the Qt-to-`Key` conversion stays in `desktop/keymap.rs`. QML-owned values (`devicePixelRatio`, grid width, `Screen`) are facts (`ScaleChanged(dpr)`, `Resized{width}`); the core computes `thumb_height = round(row_height * dpr)`.
- **cxx-qt rules (spike-proven):** a same-class `#[qenum]` works as a `#[qproperty]` type; as an invokable return or argument it makes qmlcachegen fall back (so: `i32` codes at invokable boundaries); standalone `#[qenum] #[namespace]` is not reachable by name; `Connections { function onX(a: int, b: string) }` compiles only with annotated arguments and may call id'd components and Rust methods.
- **Paths: a typed, lossless `Name` and `Path` (no in-band escapes, no stringly paths).** `pg_model::name::Name` holds the OS name exactly (WTF-8 bytes on Windows, raw bytes on Unix), stored as a BLOB; `Path` is a sequence of `Name`s plus an anchor. Only display (QML, messages) and user-typed input cross as `&str`, through `Name::display()` / `PathRules::parse()`; actions go by `FolderId`/`FileId`, never by path string. Plus `enum PathRules { Windows, Posix }` (an enum, not a trait: closed set of two, no generics through `Catalog`/`FolderTree`/cxx-qt models, both testable on every host). Rejected: an in-band escape in `String` (corrupts real names containing the escape, a convention every reader must remember) and skipping such files (hides real files). Churn through every `&str` consumer is accepted. Spec in S-17.
- **No compatibility with pre-release data.** By the project's own rule there are no schema bumps before release, so catalogs are rebuilt (`rebuild`/rescan) and key quirks are fixed rather than preserved; there are no golden-key byte-identity requirements and no old-format readers. Persisted JSON (session, `views`, prefs) gets the right format, with one one-shot converter only for the user's own saved views if cheap. Golden tests still pin the *new* formats against accidental change.
- **Facades:** a facade exists iff it holds logic with unit tests, or owns a Rust object QML must call by id (compiled-QML rule). `ViewsMenu` is extracted from `TopBar`. `Shell` is the single UI input and has two methods in spirit: `dispatch(Event)` and `execute(Command)`; anything with an `if` goes into the core.
- **The catalog keeps its private `conn`**; only what is separable without it is split (S-20).
- **Localisation: Fluent** (`fluent-bundle` 0.16 + `unic-langid`), wasm32-proven.
- **Policies:** every commit passes `just lint` and `just test`; no schema bumps before release.
- **The remaining REVIEW rows are in scope** as S-21 (Phase 4): R-75, R-76, R-77, R-78, R-80, R-83, R-101, R-112, R-113, R-127, R-66. Mount-point aliasing on POSIX (`/mnt/d` = `/mnt/e`) is not built (nothing needs it); only the tree's anchor generalisation is.
- **Ledger:** new steps S-14 to S-20 are added; IDs never change or get reused. S-13.5 is run in S-16.

## Alternatives considered (and why the plan is what it is)

Judged on: testability without Qt, fit with the spike facts, independence from the undecided web stack, regret if the web decision goes either way, and cost.

| | Alternative | Verdict |
|---|---|---|
| A | One Qt-free controller owning all data (`Grid`, `Tree`) behind a shared thread-local cell, a large Event/Command enum, named `Arm`/`Fired` timers, "the web reuses it whole" (an earlier draft) | **Rejected as drafted.** The ownership move buys nothing (`Grid` is already pure and tested) and costs a borrow protocol plus a rewrite of the two models; the web-reuse claim was unfounded; thread-per-arm timers and `Instant` do not suit wasm. Its core idea (policy out of QML into tested Rust) is kept. |
| B | Per-feature view-model structs, no global controller | Rejected: the cross-feature rules (start gate, anchor, apply-view touching folder + filters + sort + grid) have no home, which is the original bug (`--apply-view` overridden by the stored session). Its virtue, small units with their own tests, is kept inside C. |
| **C** | **One `update` entry over small sub-machines; sans-IO time with one C++ `QTimer`; data owners keep their data; shared things exposed as data/types** | **Chosen.** |
| D | Core on its own thread (actor) with channels | Rejected: `QAbstractListModel::data()` is synchronous on the GUI thread, so the actor needs mirrors of the rows, which duplicates memory and adds latency. |
| E | Policy as data and generated types only; each UI owns its behaviour | Rejected for the desktop: it leaves the Qt-side policy (`Main.qml`) untestable, i.e. gap (a) open. Adopted for what both UIs share (see the web bullet). |
| F | A general `Backend` trait (local / remote / fixture) in front of `pg-app` | Deferred: no second implementation exists. Done only where one is real: the Yandex `Source` seam (S-12.21, spike S11). Revisit if the web client turns out to be Qt-WASM, where every bridge object becomes a network client. |
| G | One UI codebase for desktop and web (Qt WASM running the same QML, or a webview with one web UI for both) | Not decided here and not needed: it is a product decision about the web stack. Cost is very high and unproven (Qt Multimedia is a technology preview on WASM). If it is ever taken, this plan loses nothing: the controller is Qt-free and wasm-clean. A Qt-WASM screen check (WEB_CLIENT.md "Open checks") is listed as an optional spike, not a blocker. |

Also weighed and kept: **MVU/commands over reactive signals** (replay and virtual time are natural in MVU, awkward in a signal graph); **Fluent over Qt's `.ts`** (the same `.ftl` serves Rust and a JS client, and Qt's tooling would not reach a non-Qt web client); **own `Name` type with a pinned WTF-8 spec over `os_str_bytes`/`std` `OsStr::as_encoded_bytes`** (both document their encoding as an implementation detail that may change, so neither is safe to persist; a crate may still be used for conversions at the OS edge); **`PathRules` enum over a trait**; **statechart libraries rejected** for the start gate (an explicit phase enum in `StartGate` is enough).

## Phase order and why

1. **Infrastructure first** (S-14 verification, S-15 CI, S-16 performance, S-18 fuzz/property tests, and S-17.0 reference-key corpus, which must run on unmodified code).
2. **S-12 completion** around the controller core.
3. **Structure:** S-17 (portable lossless model), S-20 (crate splits), S-19 (text seam). S-17 touches catalog/platform/library/model and S-12 touches client/desktop/app, so they are independent; S-12 is first so the bridge and text code are not rewritten twice.
4. **Close-out:** the final S-16 measurement and the docs rewrite.

- **S13 Pass.** Single C++ `QTimer` (`QElapsedTimer` clock) driven by a fixed script (`--spike-timer=1`, `gallery.exe` offscreen, quits itself). Fires in order `[2, 4, 6, 7, 1099, 2000]`, matching the expected list: an arm of 500 ms followed at once by 100 ms fires only the 100 ms one; a later re-arm (400 ms) fires once, not earlier; a re-arm to 300 ms after a disarm fires once; a re-arm from inside the callback runs on the GUI thread; 1000 re-arms in one callback leave one fire (generation 1099); no stray fire before the sentinel. Caveats: a bare disarm (no re-arm after it) is not separately tested; the test ran under the GUI binary, not `cargo test -p pg-desktop`, so the Qt-on-PATH test run is still unproven for this executor.

## Phase 3 — Structure

**S-17 Portable, lossless model** (S-17.0 is in Phase 1).

- **S-17.1 `Name` and `Path` types** (`pg-model::name`, pure, all hosts). `Name` owns the exact OS name: WTF-8 bytes (Windows; built from `&[u16]` with `char::decode_utf16`, unpaired surrogates kept as WTF-8) or raw bytes (Unix); canonical-form validation on construction, so two equal names are byte-equal. `Name::display() -> Cow<str>` (lossy, U+FFFD, for UI and messages only), `Name::to_native(&mut NativePath)` (exact), `Name::from_native`. `Path` is `{anchor, Vec<Name>}`; `PathRules::parse(&str)` is the one place user text becomes a `Path`. Serde: a `Name` is a plain JSON string when valid Unicode (so JSON stays readable), else `{"b": "<hex>"}`. Key functions take `&Name`; case folding applies to the valid-Unicode runs and invalid units are kept exact. Proptests: `Name` round trip on arbitrary `Vec<u16>` and `Vec<u8>`; construction canonical (equal iff bytes equal); injectivity of keys over distinct names; folding never touches invalid units; ordering stable under component splitting; serde round trip; `decode` of arbitrary bytes never panics.
- **S-17.2 `PathRules { Windows, Posix }`** (`NATIVE` by `cfg`, an instance field so Windows rules run on Linux). Methods: `sep`, `anchor`, `components`, `push_folder_key`, `push_name_key`, `is_under`, `join`, `split_file_name`, `scope_keys`, `succ_of_sep`. Windows starts from the existing logic; its keys are diffed against `reference_keys.tsv` and every difference is intended and listed (not byte-identity). Posix: empty anchor, case-sensitive; folder component key `lower(c) 0x00 exact(c) 0x01` so `Pics` and `pics` stay distinct; `name_key` already works. Unify `is_under` and `folder_key` folding (they differ for a final Σ today). Re-baseline the callgrind gates once.
- **S-17.3 Catalog takes `PathRules`.** Folder paths and file names are BLOB columns holding `Name` bytes (the schema changes in place, no bump, catalogs rebuilt). Remove the separator from SQL: select `(folder, name)` and join in Rust instead of the eight `||'\\'||` concats (`catalog/lib.rs:878,1100,1149`, `browse/read/details.rs:18`, `state.rs:48`, `fixture/state.rs:59`); bind `under_root` as `path = ?1 OR (path >= ?2 AND path < ?3)` (the `under_root!` macro relies on `]` = `\`+1, `lib.rs:89`); rewrite `file_by_path` (`lib.rs:1053-1058`) as a `folder_key` plus name-key lookup, which also fixes its ASCII-only SQLite `lower()` bug; register `pg_order_key`/`pg_contains` with the rules, `pg_contains` matching display names. A `meta('path_rules')` row is stamped at creation; a mismatch (or a catalog from before this commit) refuses to open with a typed error that says to rebuild. Catalog tests are parameterised over both rules.

## Risks (ranked)

1. The start gate moving into the core regresses in an order screenshots cannot exercise: mitigated by doing it early and small (S-12.7b), the dual-run, the exhaustive trace tests and the proptests.
2. The single C++ `QTimer` executor (S13) misbehaves under re-arm or in tests: fall back to a QML-side `Timer` driven by `next_deadline()` (the core stays sans-IO either way); decided by spike S13 before S-12.18.
3. The JSON-removal hub commit (S-12.12) changes the chain that feeds the first list: one commit, whole-hub grep, full hook matrix; the `--apply-view` fix is already in by then (S-12.7b).

4. Screenshots are not fully deterministic across the whole matrix (spike S12): fall back to a small per-pixel tolerance plus a disabled-animation flag, and say so in `just shots`.
5. The web stack is decided later and wants something this plan did not give it: the shared things are data and types and the core is Qt-free and wasm-clean, so the cost of any of the three web options is additive, not a rework. An optional Qt-WASM spike (S14) informs that decision.

6. The prefs store (S-12.19) changes a file format: no old-format readers; a one-shot converter only for the user's saved views if cheap.
7. A `lint-qml` interpreter fallback: qenum returns/arguments are known to fall back (use `i32`); `Connections` handlers need annotated arguments; thumb height comes from QML's scale.
8. The `Name`/`Path` change touches every `&str` path consumer and the catalog schema: staged S-17.1 to S-17.6 (type first, each layer converted in turn), the reference-key diff listing every intended key change, catalogs rebuilt, the catalog refuses a foreign `path_rules`.
9. Cross-crate performance after S-17/S-20 with `lto = false`: gated by S-16 checkpoints; the `PathRules` branch re-baselines the gates once.
10. Scope: roughly 80 commits. Phases 1 and 2 stand alone; S-17, S-19 and S-20 can each be dropped without affecting the others. CI cost and flakiness (Qt install, screenshots on hosted runners): the screenshot job starts informational and becomes required once stable.
