## Decisions

1. **Typed folders everywhere in Rust; text only at the QML edge.** `SavedView.folder` and `Listing.folder` become a typed merged folder (`pg_model::rules::Path`: anchor `""` or `\` for UNC, parts as `Name`; all-folders means no parts). Stored as `rules.join(path)` bytes in a `folder BLOB` column. There is no SavedView-only fallback: a lossy hop at apply-view is not acceptable at this standard.
2. **`session.folder` is typed too.** It is stored in the existing `session` key/value table as the JSON of the typed `Path`. `Name`'s serde gives a plain string when the name is valid UTF-8 and `{"b": hex}` otherwise. The `session` table keeps its shape; no schema change.
3. **The folder tree is fixed, not recorded.** `folder_tree` rows carry a `FolderId` and typed `Path` parts. `TreeBuilder` builds keys and components from the parts, never by splitting display text. QML selects a folder by its tree row's id, which Rust owns. `Shell.folder` and `FolderModel.mergedPath` remain display text, for the title and the Hud only. This is done in the same change as the S-17.4 `FolderTree` anchor work (`drives: u32` becomes `anchors: u64`), because both rewrite the same code, and the S-17.4 ledger row is updated in that change.
4. **Browse reads are rules-aware.** `scope` uses `rules.scope_keys(parts, recursive)`; `facets` and `list_grid` take the typed folder; the tree is built by parts. Without this the Posix run cannot pass, so it is part of item 1, not an extra.
5. **Qt argv: leave `gui_app.cpp` as it is.** Decided by the probe (Step 6): `QCoreApplication::arguments()` was exact with our argv and with `__argv`, so `__argc/__argv` is not adopted. No app path depends on Qt's argv either way.
6. **Animation player by file id.** `AnimationPlayer` gets `fileId` instead of `source`. Rust resolves it through `file_source(id)` and `pg_platform::names::path_buf(rules.join(..))`, and `Player::start` takes a `PathBuf`. No path string is built in QML for the player. `findSimilar` also carries the file id, because it acts on the path. `viewedFilePath` stays display text for the Hud. Video `fileUrl` stays a Qt URL (QUrl and Qt Multimedia/FFmpeg cannot carry a lone surrogate, and the video crate already refuses such names). It is empty, not lossy, when the path has no UTF-8 form, so it never opens a different file.

## Risks and open questions

- Size: steps 1 to 4 touch about 25 files across six crates, and the S-17.4 change is bundled. The ripple through the client controller, the tree and the QML edge is the main risk. Do it in one change, with the full shots matrix.
- Session JSON: a `session` value written by the new code is not readable by the old one. Catalogs are rebuilt before release and there are no old-format readers, so this is accepted.
- The Qt `__argv` route: resolved by the probe (Step 6). `__argv` is populated for the Rust `main` (it printed `70 72 6F 62 65 …`), but the route was not adopted because Qt's `arguments()` was already exact.
- Linux behaviour of the desktop crate cannot be built (Qt). The typed-path changes in `pg-desktop` are compiled and tested on Windows only.
