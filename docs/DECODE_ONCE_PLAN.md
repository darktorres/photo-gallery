# Decode each new file once, feature toggles, incremental grid fill: phased plan

## Context

A new file is read and decoded three times by three passes (`Inner::round` in `crates/library/src/runner.rs`: Crops, Scans, **Import**, **Borders**, **Thumbs**): import decodes DCT-scaled to >= 512x320 (`Analyzer::analyze_image`), borders decode full-size in stored
orientation (`Analyzer::find_borders`), thumbs decode scaled to >= 4x grid height (`Maker::make_image`). `D:\wallhaven\downloads` (queried this session): 46,434 files / 170 GB, 68% JPEG (avg 3 MB, wallpapers: 1080p decodes at 1/2, 4K at 1/4 for the import), 32% PNG (avg 5 MB);
Kingston NVMe, 12 logical cores, 64 GB RAM, so the work is **CPU-bound**. The user paused at borders, so the thumbs pass never ran and tiles were made on demand while scrolling (`providers.cpp`: 8 Normal-priority threads). Open item R-86 (`docs/REVIEW.md`).

## Decisions (all given by the user)

- Merge the three stages for files whose analysis is due, **and adopt the hash redefinition on the full decode unconditionally** (no measurement gate). Hashes of non-JPEG formats and of JPEGs with denom 1 do not change.
- Remove the "no version bumps before the first release" rule from the repo; bump versions as needed.
- Three toggles (border detection, duplicate detection, pre-generated thumbnails), default on. A control that depends on a disabled feature **stays enabled like the others; clicking it shows a popup saying the feature is disabled instead of performing its action** (not hidden, not greyed out; confirmed by the user's clarification).
- Thumbnails of first-import files run at below-normal priority (was Idle): confirmed. Pass order Thumbs before Borders: confirmed. UI and render threads above normal priority (Windows): confirmed. Tile-pool priority: left out. Mid-decode cancellation: declined.
- **Incremental grid updates** (no whole-list reloads during an import), because catalogs will grow large.
- Thumbnail tiers (master thumbnail, derived heights): **still undecided; keep thumbnails as they are**.
- A README note is enough for the "older build rebuilds a migrated catalog" case.
- Process: **wait for the Modularity work to land** (the user will say when). Then implement **one phase at a time: implement, commit on `main`, next phase. No cargo, tests, benches or other validation between phases; validation happens once, at the end (Phase 6).**
  Fixes found in validation go in a closing commit. (No new branches; commit only the phase's files, never the user's other work.)

## Phase 3: duplicate hashes on the full decode, and the duplicate toggle (migration 3)

- **New hash definition (adopted):** `pixel_hash` = xxh3 of the upright **full-size** pixels; PDQ and ThumbHash fitted from that image (ThumbHash from the 512 image only when `fit_within` produced one, it returns false for images <= 512 px). Implemented once in `Analyzer::hashes(bytes, turns)` (full stored decode -> `orient_into` -> hashes; upright dims via `Info::upright()`, which exists in `codec/src/decode.rs` and becomes `pub`),
  used by `analyze_image` and by the catch-up pass, with a parity test. Hashes of PNG/WebP/GIF/BMP/TIFF and JPEGs with denom 1 are unchanged; JPEGs with denom > 1 change.
- **Migration 3** (`MIGRATIONS` beside `TO_2_CHANGE_STAMPS`): `analysis.dups_due INTEGER NOT NULL DEFAULT 0` + a partial index like `analysis_borders_due` (the `CREATE INDEX .. WHERE` scans `analysis` once inside `prepare`: fine at 46k, minutes at 70M), **and the `dups_version` meta seed** (`INSERT INTO meta`; `set_borders_version` errors on a missing key; `carry_rows`/`SEEDS` compare meta keys).
  `Versions` gains a `dups` field (11 struct-literal sites: `catalog/tests/other_process.rs`, `bench/benches/ir/catalog.rs`, `catalog/src/browse/writes.rs`, `pair.rs`, `scan/src/lib.rs`, `thumbs/src/lib.rs`, `browse/read/tests.rs`, `browse/fixtures.rs`, `thumbcache` fixtures, `library/src/lib.rs`, `catalog/src/test_support.rs`; all 11 re-confirmed). Fresh and migrated schemas compare equal (`expected()` = baseline + migrations); add the missing migration test.
  README note: an older build opening a migrated catalog moves it aside as `catalog.sqlite.replaced` and rebuilds, losing pairing state.
- **`DUPS_VERSION` = 2** via `set_dups_version` (mirror of `set_borders_version`, run from `Catalog::prepare`): one transaction NULLs `pixel_hash`, `pdq`, `pdq_quality`, `pdq_dihedral`, deletes `pdq_pairs`, and sets `dups_due = 1`, **only for rows whose stored format is JPEG** (other formats' hashes are unchanged); it stamps `files.changed` explicitly (no trigger fires). No mixed definitions are ever compared. `IMPORT_VERSION` stays 1 (bumping it re-pends every file and wipes stored borders/pairs).
- **Model/queries:** `ImageFacts.pixels: Option<PixelHashes>`; invariant `pixel_hash`/`pdq`/`pdq_quality`/`pdq_dihedral` NULL together. Nothing checks it today (`Catalog::pdq_hashes` only errors on `pdq_dihedral IS NULL AND pdq_quality >= MIN_QUALITY`), so `store_analysis`/`store_hashes` write the four together, `pdq_hashes()` skips `dups_due = 1`, and a test pins the invariant after a `DUPS_VERSION` bump. `dups_due` = `pixel_hash IS NULL AND kind = 'image' AND error IS NULL`, written explicitly by `store_analysis` (the `INSERT OR REPLACE` column list resets omitted columns).
  `pg_import::import` takes an options struct (`ImportOptions { features, .. }`: ~18 call sites: runner, cli, `thumbs` test, `library/tests/*` incl. `writeback.rs` x9) and, with dups off, skips hashing and does not load `pdq_hashes()`/`Pairer::build`; `Pairer::reserve` sized from the dups-due count.
- **`Dups` catch-up pass:** worklist `Catalog::pending_dups()` mirroring `pending_borders` (`work_columns!`, `dups_due = 1 AND missing = 0 AND pending = 0 ORDER BY volume, file_ref & 0xFFFFFFFFFFFF`); round order `Crops, Scans, Import, Thumbs, Borders, Dups`; priority `BelowNormal`; `Phase::Dups` (`jobs/src/control.rs`; matches in `cli/src/report.rs` `phase_label`, `desktop/src/library.rs`), `text::Pass::Dups`,
  `Message::PassDups` (`client/src/text/message.rs`), `pass-dups` in `text.ftl`. The pass's code goes in a new crate `pg-dups` beside `pg-borders` (M-15 pattern; `import`-level line in `crate-layers.txt`: `analysis catalog dedup jobs`, and `library` gains it). `store_hashes` (a new writer in `writers.rs`) checks size, mtime, **rotation** and `not_being_written!()` and runs the `delete_pairs` statement; hash and pair writes **stamp `files.changed` for both files of every pair** (they stamp nothing today, so neither the grid nor the incremental merge of Phase 4 would see them). Terminal states: io error stays due; decode error -> `store_failure`.
- Duplicates checkbox + pref `detect_duplicates` + count + the disabled-feature popup (Phase 2 pattern) on the duplicates combo. Because the combo is blocked while off, the stale-filter case (`NOT_DUPLICATES` listing near-duplicates under "No duplicates" when tier 0b/1 hashes are NULL) cannot occur from the UI.
Tests: `Analyzer::hashes` == `analyze`; unchanged hashes for PNG/WebP/denom-1 JPEG; off -> hashes NULL and `dups_due = 1`; on -> catch-up fills and pairs; version bump re-arms JPEG rows only; migration test; `pdq_hashes` skips due rows.

## Phase 4: incremental grid updates

Recommended design (research): a **stamp-keyed delta merge** (the unused `changes_since` / `files.changed` mechanism was built for it, `catalog/src/browse/read/changes.rs`).

- **Today:** `Session::grid(folder, recursive, query, sort, deliver)` (`app/src/reader.rs`, request `Kind::Grid`) delivers a full `Vec<Entry>` from `browse::read::list_grid` to a callback; rows live in `Grid.entries` on the GUI thread (`client/src/grid.rs`) and `GalleryModel` exposes one Qt row per layout row (`desktop/src/gallery/`, split by M-12: `model.rs`, `items.rs`, `state.rs`, ...); `onImported` (`Main.qml`) -> `refreshGrid()` -> `shell.reloadList()` re-queries everything. During an import the row set is already complete from the scan; imported batches mostly *update* entries (aspect 1.0 -> real, cut, borders),
  and for the 8 analysis-based sort keys (Taken, Megapixels, Width, Height, AspectRatio, Duration, Frames, Borders) rows also *move* (NULL sorts last).
- **Catalog:** `list_grid_delta(folder, recursive, query, sort, since)` (beside `list_grid` in `catalog/src/browse/read/grid.rs`) returns, in one read transaction with the stamp, `(Entry, sort value)` for files with `changed > since` that match the current listing (same `grid_sql` WHERE clause, `AND f.changed > ?`), plus the changed ids (so rows that left the filter or went missing are found as "changed but not returned").
- **Shared ordering:** `compare_keys` is in `catalog/src/browse/read/grid.rs` but `pg-client` may depend only on `pg-model` (`crate-layers.txt`), so it moves to `pg-model` beside `order_key` (`model/src/rules.rs`), with the sort-value type; the catalog and the client both use that one copy (no re-export; callers updated).
- **App:** `Session::grid_delta` with its own request kind `Kind::GridDelta` (must not cancel a full-list request; a full reload in flight supersedes it; a delta computed against an older generation is dropped).
- **Client (`Grid`):** keep a parallel `Vec` of sort values plus `order_key`, and an id -> index map (`position_of` is a linear scan today); `merge(delta)` does binary-search insert / remove-and-reinsert / in-place update with exactly `compare_keys` semantics (NULL last in both directions, ties by `order_key`, then id); selection, anchor and current remapped by file id
  (as `selection_after` already does); while the viewer is open, merges are held like the full list is (`Grid.held`) or `viewing` is remapped by id. Any inconsistency (generation or count mismatch) falls back to the full reload.
- **Layout/model:** `RowChange::between` (`client/src/layout.rs`) represents one contiguous changed range; a mid-list insert reflows every row after it, so a merge marks everything from the first changed row on as changed and adds/removes tail rows (`dataChanged`, `beginInsertRows`/`beginRemoveRows` are bridged). The justified layout is relaid whole per applied merge (O(n)); merges are coalesced/throttled (about once a second). Incremental layout is out of scope (noted as the 1M-row bottleneck).
- **Events:** `Change` (`jobs/src/events.rs`) stays a payload-free `Copy` enum (the `Bus` drops the oldest events, so payloads would be lossy). `Imported` becomes a throttled per-flush **tick**; the consumer keeps its own `since` stamp and asks for the delta (lost ticks are harmless: the stamp is a watermark). The pump already coalesces per event-loop turn (`desktop/src/library.rs`).
  `onImported` calls the incremental path; `Scanned` (scan finished: new/removed files, tree) keeps the full reload. `imports_done` keeps meaning "passes finished" (tests and `Generation` read it); the tick gets a separate counter. Facet counts and the folder tree refresh on pass end and at a slower interval, not per merge.
- Pitfalls to cover with tests: merge == full reload for **all 14 sort keys, both directions**, with filters that files enter/leave; ties; NULL keys; selection/anchor stability when rows insert above; viewer open; memory (+16-32 bytes per row for keys and the map); a delta racing a scan.

## Phase 5: first-import merge (one decode per new file)

For files whose analysis is due, one decode feeds every enabled stage; the catch-up passes (Thumbs, Borders, Dups) stay separate and unchanged. (A unified catch-up worklist was rejected: an OR join scans every file each round, depends on a healthy cache and needs watermark rework.)

- **Decode choice** (F = full stored decode, T4 = `MinSize::Upright(0, 4*height)`): any of borders / dups on -> **1 F** (borders run on it as decoded, then `orient_into`, then hashes (Phase 3 `Analyzer::hashes` logic), ThumbHash, thumbnail via `Resizer::to_height` from F). Thumbnails only (borders and dups off) -> **1 T4** feeding ThumbHash and the thumbnail. All off -> one reduced decode.
  Accepted: modes that compute hashes now always use F, so dups-only and dups+thumbnails (borders off) cost more than before. Videos: the poster frame decoded for analysis also feeds the thumbnail (`Maker::encode_frame_into`), before `trim()` (`video()` is not reusable as written).
- **Per-stage results:** the worker returns `analysis: Result<Analyzed>` (Err -> `store_failure`; the merged pass takes only analysis-due items), `borders: Skipped | Done(Option<Detection>) | Failed`, `thumb: Skipped | Done(Vec<u8>) | Failed`. Borders Failed (non-io) -> `store_borders(None)` as the catch-up does; Skipped -> nothing (`store_analysis` leaves `borders_due` armed);
  thumb Failed -> not stored, the Thumbs catch-up retries (panics are not retried). The detector runs in its own `panics::guard` (+ `AssertUnwindSafe`); after a caught panic reset the `Detector`.
- **Writes:** one catalog transaction holds `analysis_writer` and `borders_writer` (both borrow `&Tx`; drop before `commit`): `store_analysis` (resets borders/pairs), then `store_borders` only if it returned true, then `store_hashes`/pair inserts. After the commit, thumbnails of accepted files go to `cache.put_batch(.., Some(height))` in 200-thumb batches; the `Source` comes from the `WorkItem` (mtime, rotation); the cache has no foreign key to the catalog.
  A failed transaction drops its thumbnails (the Thumbs catch-up makes them); a crash between commit and `put_batch` loses only thumbnails.
- **Cache failures never fail the import:** a new `ThumbCache::is_enabled()` (`store.is_some()`; no such method today); `put_batch` errors become a notice, not `?`; a `cache_full` flag stops workers producing thumbnails for the rest of the pass; `Notice::CacheFull` published; keep the failure list. The thumb stage runs only when the toggle is on and the cache is enabled. Read the grid height at each flush and drop thumbnails of a stale height.
- **Encoder split:** `Maker` into an encoder half (`Resizer`, `small`, `Compressor`, `jpeg`) and a decode half, so `encode_image` takes `&Rgb`; the on-demand path (`make_image`, `encode_frame_into`, and `app/src/images.rs` through the `Makers` pool in `app/src/makers.rs`) keeps working with no borrow conflict (the pattern `make_from_file` uses for `file`). The ingest worker holds one `Decoder`, one `Resizer`, one image + `spare`, and one keep policy: there are two `KEEP_BYTES` today (`analysis/src/analyze.rs` 96 MB, `render/src/maker.rs` ~18.9 MB); the shared image takes the analyzer's (a parameter), the encoder keeps the maker's.
  Redefine the `kept_buffers_give_what_new_ones_do` parity test (ingest thumbnails are not byte-equal to on-demand ones).
- **Bounded decode (the user asked why):** `decode_jpeg` has no size cap (only the non-JPEG `Codecs` path checks `max_decode_bytes`, 512 MiB); a huge or hostile JPEG header makes `out.pixels.resize(w*h*3)` fail and Rust **aborts the process** on allocation failure. The merge makes every new JPEG take a full decode, widening the exposure. Add the same 512 MiB check before any full JPEG decode; over the cap: analysis from the
  scaled decode, borders recorded "none" (terminal), no full-size thumbnail; the same cap in the Borders catch-up. (Default kept unless the user drops it.)
- **Memory:** share one image buffer; free big buffers after each file; the validation phase reports peak RSS on an adversarial stratum. A decode lease in `pipeline.rs` is the contingency, not part of this phase.
- **Priority:** the merged pass is `BelowNormal` including its thumbnail and border work (confirmed); catch-up passes keep theirs (Thumbs `Idle`, Borders/Dups `BelowNormal`). Record the change from Idle in `crates/README.md` and the `pg_thumbs` header; update `docs/PLAN.md` (the two places that say thumbnails are a background task after the import: new files' thumbnails now come from the import).
- **Grid fill:** per-flush tick from `pg_import::import` (a callback), throttled; the incremental merge of Phase 4 consumes it.
- **CLI:** `gallery import` takes `--no-borders`, `--no-duplicates` and an optional `--thumbs-height` (opens the cache like `gallery thumbs`); the `import` crate Cargo comment ("not on the thumbnails or the writes") is updated and it gains `pg-render`, `pg-thumbcache` (both on earlier lines of `crate-layers.txt`, so allowed: the `import:` line gains them in the same commit). Borders are stored through `tx.borders_writer()` (`pg-catalog`); the detector is `pg-analysis`'s, so no edge to `pg-borders`. `borders paths/--csv/--stdin` keep calling `Analyzer::borders` (`eval/imgload.py` uses `--stdin`).
- **Costs known:** a stop loses up to ~580 files of merged work and the next round rebuilds `Pairer`; the one-time JPEG re-hash from Phase 3 is a full-decode Dups pass per existing library.
Tests: borders from the merged path == `find_borders` on existing fixtures; upright dims per rotation; animated/tiny images get no borders but still analyze; video poster thumbnail; detector panic keeps analysis + thumbnail and resets the detector; catch-up-only io errors never replace a good analysis; **a new file is decoded once** (decoder call counter hook) and the catch-up passes then find nothing to do;
cache disabled/full does not fail the import; all 8 toggle combinations.
Benches written here (run in Phase 6): PNG, WebP, 12 MP JPEG inputs; per-file borders and merged-import benches in `crates/bench/benches/ir/` (`bench`'s `crate-layers.txt` line gains `import` if the merged bench calls it).
